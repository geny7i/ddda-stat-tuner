# DDDA Stat Tuner

Dragon's Dogma: Dark Arisen の育成経路を組み立て、ステータスを確認するブラウザーアプリです。バックエンドを使わない静的 SPA として開発しています。

育成経路の編集、ステータス表示、職業比較チャート、共有 URL による復元、免責事項を実装しています。Phase 1 の範囲と判断記録は [Phase 1 リメイク計画](docs/phase1-remake-plan.md)、今後の操作性改善は [Phase 2 操作性改善計画](docs/phase2-improvement-plan.md) を参照してください。

職業・レベル帯・成長値とステータス計算のモデルは追加済みです。計算ルールは [育成経路とステータス計算](docs/domain-model.md) を参照してください。

トップ画面ではレベル帯を選び、左側の職業と成長値の一覧にある ×1/×10/×100 を右側の育成経路へドラッグして追加できます。配置済みの職業を別の職業へドラッグすると 1Lv入れ替えます。× ボタンを選んで「選択を追加」でも追加でき、追加元は選び直すまで維持されます。配置済み職業の「入替対象に指定」を選ぶと、別の職業へ「1Lv入替」できます。入替元の職業が残る間は指定が維持され、続けて入れ替えられます。「1Lv削除」で1Lv減らせます。Space と矢印キーでもドラッグでき、Escape で中止できます。職業一覧と配置済み職業はそれぞれ内部でスクロールできます。狭い画面では一覧と育成経路が縦に並びます。

現在のステータスとレベル帯の選択ボタンは、育成計画をスクロールしても画面上部に表示されます。レベル帯の選択ボタンには、各レベル帯で選択済みの職業をアイコンとLv数で表示します。狭い画面ではボタン列とボタン内の内訳を横にスクロールできます。

「自動調整」では HP、ST、物理攻撃、魔法攻撃、物理防御、魔法防御のいずれかを選び、未選択レベルをその能力の成長値が最大の職業で一括入力できます。選択済みの職業は変更しません。実行前に対象件数と説明を確認でき、実行後に追加件数を表示します。

現在のステータスは育成経路と体格の変更に合わせて更新されます。編集中のレベル帯では職業ごとの 1 レベル分の成長値と追加・変更操作を同じカードで確認できます。成長値の項目名は `hp`、`st`、`atk`、`matk`、`def`、`mdef` と略記します。「注目するステータス」のチェックを切り替えると、選んだ項目のスコア順に職業を並べ替えます。HP と ST は 10 分の 1、その他はそのままスコアへ加算します。

チャート画面では、トップ画面と同じ育成経路、レベル帯、注目するステータスを使い、職業ごとのスコアを棒グラフと表で比較できます。ナビゲーションで画面を移動しても編集中の状態は保たれます。

「共有 URL をコピー」を押すと、現在の育成経路と体格を含む URL をクリップボードへコピーします。`#/restore?c=...` の URL を開くと同じ内容を復元します。既存の `#restore?c=...` 形式にも対応します。不正なコードでは内容を変更せず、エラーと育成計画へ戻るリンクを表示します。

## 必要な環境

- Node.js 24.21.0（`.tool-versions` に固定）
- npm 11

## 開発

```sh
npm ci
npm run dev
```

Vite が表示する URL を開いてください。画面の経路にはハッシュ形式（`#/chart` など）を使用します。

## 確認コマンド

```sh
npm run check       # 型検査、lint、整形検査、単体テスト、ビルド
npm run test:e2e    # 本番用ビルドを生成し、プレビューに対してブラウザーテスト
```

ブラウザーテストの初回実行前に `npx playwright install chromium` で Chromium を用意してください。

## 静的ファイルの生成

```sh
npm run build
npm run preview
```

生成物は `dist/` です。`npm run preview` は生成済みの `dist/` を確認するために使います。

公開先がドメイン直下の場合は `dist/` の内容をそのまま配信します。サブパスへ配置する場合は、ビルド時に先頭と末尾の `/` を含む `APP_BASE_PATH` を設定してください。

```sh
APP_BASE_PATH=/stat-tuner/ npm run build
```

公開先では設定したパスから `index.html` とアセットを配信してください。画面の経路は URL のハッシュ内にあるため、サーバー側の経路書き換えは不要です。公開後はトップ、`#/chart`、`#/disclaimer` への直接アクセスと再読み込みを確認します。

共有 URL は現在開いている配置先を基準に作成するため、公開先のホスト名をコードへ固定していません。公開先の変更時には既存の共有 URL の到達先も確認します。
