# DDDA Stat Tuner

Dragon's Dogma: Dark Arisen の育成経路を組み立て、ステータスを確認するブラウザーアプリです。バックエンドを使わない静的 SPA として開発しています。

育成経路の編集、ステータス表示、職業比較チャート、共有 URL による復元、免責事項を実装しています。各段階の仕様は [Phase 1 リメイク計画](docs/phase1-remake-plan.md)、[Phase 2 操作性改善計画](docs/phase2-improvement-plan.md)、[Phase 3 UI/UX 調整計画](docs/phase3-ui-ux-plan.md) を参照してください。

職業・レベル帯・成長値とステータス計算のモデルは追加済みです。計算ルールは [育成経路とステータス計算](docs/domain-model.md) を参照してください。

体格の上にある「キャラクター」で覚者／ポーンを選べます。初期値は覚者です。入力済みの計画で種別を切り替えると、確認後にLv1を含むすべての職業入力をリセットし、体格と注目するステータスは維持します。キャンセルすれば入力は変わりません。入力が空なら確認なしで切り替わります。ポーンではアサシン・マジックアーチャー・ミスティックナイトを選べず、手動編集・自動調整・比較チャートも使用可能な職業に限定されます。

トップ画面ではレベル帯を選び、左側の職業と成長値の一覧にある ×1/×10/×100 を右側の育成経路へドラッグして追加できます。配置済みの職業を別の職業へドラッグすると 1Lv入れ替えます。× ボタンを選んで「選択を追加」でも追加でき、追加元は選び直すまで維持されます。配置済み職業の「入替対象に指定」を選ぶと、別の職業へ「1Lv入替」できます。入替元の職業が残る間は指定が維持され、続けて入れ替えられます。「1Lv削除」で1Lv減らせます。職業カード右上の × でそのレベル帯の該当職業を全Lv削除できます。詳しい操作は育成計画の見出し横にある「使い方」から確認できます。職業一覧と配置済み職業はそれぞれ内部でスクロールできます。狭い画面では一覧と育成経路が縦に並びます。

現在のステータスとレベル帯の選択ボタンは、育成計画をスクロールしても画面上部に表示されます。レベル帯の選択ボタンには、各レベル帯で選択済みの職業をアイコンとLv数で表示します。狭い画面ではボタン列とボタン内の内訳を横にスクロールできます。

「自動調整」では HP、ST、物理攻撃、魔法攻撃、物理防御、魔法防御のいずれかを選び、未選択レベルをその能力の成長値が最大の職業で一括入力できます。選択済みの職業は変更しません。全200Lvを選択した後は、Lv1〜10を維持したまま全6ステータスを5または10の倍数に調整できます。変更上限は覚者が26Lv、ポーンの5倍数が12Lv、10倍数が23Lvです。相対的に高い能力とスコアの低下を抑え、変更前後の値を表示します。すでに条件を満たす場合は変更しません。

ポーンの10倍数調整には、Lv2〜10のメイジ成長回数が奇数である必要があります。Lv1の初期職業は回数に含みません。偶数の場合は理由を表示し実行を無効にしますが、5倍数は利用できます。未完成の経路ではまず残りLv数を案内します。探索中に種別・経路・体格を変更すると探索を中断し、古い結果を適用しません。詳しくは [Phase 5 倍数調整](docs/phase5-rounding-adjustment.md) と [ポーンの成立条件・到達性](docs/phase6-pawn-rounding-verification.md) を参照してください。

現在のステータスは育成経路と体格の変更に合わせて更新されます。編集中のレベル帯では職業ごとの 1 レベル分の成長値と追加・変更操作を同じカードで確認できます。成長値の項目名は `hp`、`st`、`atk`、`matk`、`def`、`mdef` と略記します。職業一覧の見出し直下にある「注目するステータス」のチェックを切り替えると、選んだ項目のスコア順に職業を並べ替えます。HP と ST は 10 分の 1、その他はそのままスコアへ加算します。

チャート画面では、トップ画面と同じ育成経路、レベル帯、注目するステータスを使い、職業ごとのスコアを棒グラフと表で比較できます。ナビゲーションで画面を移動しても編集中の状態は保たれます。

「共有 URL をコピー」を押すと、現在の種別・育成経路・体格を含む URL をクリップボードへコピーします。`#/restore?c=...` の URL を開くと同じ内容を復元します。復元時は種別切り替えのリセット確認を挟まず、保存された経路をそのまま表示します。既存の `#restore?c=...` 形式にも対応し、種別を含まない旧コードは覚者として復元します。不正な種別やポーンの禁止職業を含むコードは内容を変更せず、エラーと育成計画へ戻るリンクを表示します。

## 必要な環境

- Node.js 24.21.0（`.tool-versions` に固定）
- npm 11

## 開発

```sh
npm ci
npm run dev
```

Vite が表示する URL を開いてください。画面の経路にはハッシュ形式（`#/chart` など）を使用します。

## 使い方ページ

使い方ページは `#/help` を直接開いて確認できます。チャートと育成計画の使い方モーダルからの導線変更はPhase 7の次のPRで行います。

## 使い方本文と画像の編集

本文は [src/content/help.md](src/content/help.md) を編集します。通常のMarkdownで段落・箇条書き・強調・リンク・コード・表・画像を書けます。生HTMLは表示しません。ページタイトルはアプリ側にあるため、本文は `##` から始めてください。`##` と `###` の見出しが目次に自動で入り、追加・削除・並べ替えにも追従します。

画像は `public/help/images/` に置き、次のように挿入します。`./images/` は本文用の画像記法で、Markdownファイルの物理的な相対パスではありません。公開先のベースパスに合わせてアプリがURLを変換します。

```markdown
![画像の内容を説明する代替テキスト](./images/editor-example.png)
```

`editor-example.png` は育成計画の画面キャプチャです。新しい画像は同じディレクトリに別の名前で保存し、代替テキストを付けてください。ルート配信でもサブパス配信でも同じ記法を使えます。

目次リンクのURLは `#/help?section=...` です。本文から見出しへリンクする場合は、目次のURLにある `section` の値を使い、`[スコアについて](#help-スコアについて)` のように記載します。育成計画へのリンクは `[育成計画へ戻る](/)` と書けます。見出しの文言を変更するとIDも変わるため、手書きの見出しリンクも合わせて更新してください。

`npm run dev` で `#/help` を開いて本文・目次・画像を確認してください。公開内容へ反映するには `npm run build` で生成した `dist/` を再公開します。サブパス配信の確認では、ビルドとpreviewに同じベースパスを設定します。

```sh
APP_BASE_PATH=/stat-tuner/ npm run build
APP_BASE_PATH=/stat-tuner/ npm run preview
```

previewの `/stat-tuner/#/help` で画像と節への移動を確認してください。

## 確認コマンド

```sh
npm run check       # 型検査、lint、整形検査、単体テスト、ビルド
npm run test:e2e    # 本番用ビルドを生成し、プレビューに対してブラウザーテスト
```

ブラウザーテストの初回実行前に `npx playwright install chromium` で Chromium を用意してください。

## 静的ファイルの生成

```sh
npm run build
npm run preview
```

生成物は `dist/` です。`npm run preview` は生成済みの `dist/` を確認するために使います。

公開先がドメイン直下の場合は `dist/` の内容をそのまま配信します。サブパスへ配置する場合は、ビルド時に先頭と末尾の `/` を含む `APP_BASE_PATH` を設定してください。

```sh
APP_BASE_PATH=/stat-tuner/ npm run build
```

公開先では設定したパスから `index.html` とアセットを配信してください。画面の経路は URL のハッシュ内にあるため、サーバー側の経路書き換えは不要です。公開後はトップ、`#/chart`、`#/disclaimer` への直接アクセスと再読み込みを確認します。

共有 URL は現在開いている配置先を基準に作成するため、公開先のホスト名をコードへ固定していません。公開先の変更時には既存の共有 URL の到達先も確認します。
