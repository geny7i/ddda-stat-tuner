# Phase 5 倍数調整

この資料は覚者（全9職）の探索と保証を記載する。Phase 6で追加したポーンの成立条件と変更上限は [ポーンの倍数調整の到達性](phase6-pawn-rounding-verification.md) を参照。

全200Lv入力済みの育成経路を、全6能力が5または10の倍数になるよう調整する。現在の成長表では、元の経路と体格によらず最大26Lvの変更で解を返す。Lv1〜10は維持する。

## 到達性

Lv101〜200の各職業は、HP/STが5の倍数、HP+ST=20、攻撃+魔攻+防御+魔防=4という成長値を持つ。

10の倍数にするために前半で必要な条件は以下のとおり。

- HP/STのmod10が `(0,0)` または `(5,5)`。
- 残り4能力の合計のmod10が0。

前半の状態を `((HP-ST) mod 10, ST mod 5, 4能力合計 mod 10)` とすると500状態になる。Lv11〜100の14Lv分で全状態を実現でき、変更先からMageを除いても成立する。

後半はHPのmod10が0か5の2通り、攻撃・魔攻・防御のmod10が各10通りで、2,000状態になる。STと魔防は保存条件から決まる。12Lv分で、そのLv数の保存条件を満たす全状態を実現できる。

任意の前半14Lvを再割り当てして前半条件を整え、任意の後半12Lvを再割り当てすれば完成する。したがって、前半90Lv・後半100Lvすべてを変更候補として探す際も、各区間に14Lv・12Lv以内の解が存在する。

5の倍数では両区間とも125状態に圧縮できる。同じ14Lv・12Lvの上限で解ける。

## 探索と評価

各区間について、元経路の各レベルを1回ずつ処理する動的計画法を使う。変更しない選択も含め、各剰余状態の最良候補と復元情報を保存する。元の職業の数を超える入替は起こらない。候補数による打ち切りは行わない。

能力ごとの個別の到達可能最大値を `max`、調整前の値を `before`、1Lvの変更による差を `delta` として、各変更に次の損失を付ける。

```
能力損失 = Σ max(0, -delta) × before / max²
スコア損失 = 0.25 × max(0, -スコア差) / 調整前スコア
```

能力損失は低下率に `(before/max)²` を掛けたもの。HP/STと他の能力の尺度をそろえ、その能力の最大値に近い強みを重く評価する。前半ではMageへの新たな変更を候補から除く。既存のMageを維持する選択は可能。

まず、上記損失と1Lvあたり0.0002の変更ペナルティの合計を最小化する。区間の変更上限を超えた場合はペナルティ0.002で再探索し、なお超える場合は変更数を最優先、損失を次優先として探索する。最後の探索は変更数を最小化するため、証明した上限以内の解を必ず返せる。同評価では変更数、スコア差も比較し、結果を決定的にする。

すでにすべての能力が指定倍数なら変更しない。前半の条件をすでに満たしている場合も前半は維持し、後半だけを調整する。

これは各変更の損失を加算する評価であり、変更による増減の相殺や、前半の別候補による後半の改善まで含む全体最適化ではない。最高スコア・最小変更数・強みの完全維持は保証しない。解の存在と最大26Lvという変更上限は保証する。

## 検証

- 成長表を独立に全列挙し、前半14Lv・後半12Lvの到達性を確認。
- 全9職業への偏った経路と全5体格、固定シードの混在20経路で5・10両方の成功を検証。
- 変更数、前半・後半の上限、元データの不変性、Mage非増加、丸め済み経路の維持を検証。
- 物理攻撃特化の例で攻撃低下3%以内、スコア低下5以内を回帰検証。この品質の数値は全経路への保証ではない。
- 画面からの実行、以前未発見だった経路、共有URLでの復元、モバイル幅の表示をE2Eで検証。
