# Phase 3 UI/UX 調整計画

## この文書の位置づけ

この文書は Phase 3 の要求、採用する仕様、実装順、受け入れ条件をまとめたもの。計画書だけで実装とレビューを進められるようにする。計画書の PR では画面・状態・テストを変更しない。Phase 2 で追加した職業と成長値の統合、レベル帯の内訳、自動調整を維持する。

## 要求の背景と対象

[移植元アプリ](https://geny7i.github.io/ddda-planner/)で重視していた「現在のステータスを見ながら職業を細かく選ぶ」体験を、リメイク版の育成計画でも実現する。現在の 6 ステータスとレベル帯の切替を、職業一覧を操作している間も画面内に置く。後半の職業から育成経路へドラッグするときも、追加先を同時に見られるようにする。

合わせて、10Lv・100Lv のドラッグ中表示の改行、入替操作の分かりにくい文言、二種類の選択状態の見えにくさを直す。注目するステータスを職業一覧へ移し、常時表示している操作説明を見出し横のヘルプへ収める。ヘルプの文章は初稿として扱い、後から文言だけを調整できるようにする。

## 目的と完了条件

育成計画で職業を選びながら、現在の 6 ステータスとレベル帯を常に確認・操作できるようにする。後半の職業からも育成経路へ無理なくドラッグでき、選択中の追加元・入替元が視覚と読み上げの両方で分かるようにする。

完了条件は次のとおり。

1. デスクトップと幅 390px 相当の画面で、職業一覧の末尾を見ていても 6 ステータスとレベル帯の切替操作が画面内にある。
2. 職業一覧の末尾から、表示中レベル帯の育成経路へドラッグで追加できる。既存のボタン操作でも同じ結果を得られる。
3. 追加元または入替元の選択が明確で、両者が同時に選択された状態にならない。
4. ×10・×100 のドラッグ中表示が改行で崩れない。
5. 文言、ヘルプ、注目ステータスの配置が下記仕様に一致する。
6. 編集結果、職業制限、上限、自動調整、チャート、共有 URL に回帰がない。

## 現状と採用するレイアウト

現在は `EditorPage` の上からステータス、共有、自動調整、体格、レベル帯、注目ステータス、職業一覧・育成経路の順に並ぶ。`PathEditor` はデスクトップで左右 2 列、幅 760px 以下で上下 1 列になる。職業一覧はページ全体と一緒にスクロールし、育成経路も画面外へ流れる。

### 採用案: コンパクトな上部バーと編集領域内のスクロール

育成計画の見出しの下に「現在のステータス」と「レベル帯」を一つの固定バーとして連続配置する。バーは編集画面のスクロール中に `position: sticky; top: 0` で追従する。サイトのナビゲーションは固定しない。固定バーの高さを抑え、ページ本文の操作領域を確保する。

- ステータスは現在の Lv と HP、ST、物理攻撃、魔法攻撃、物理防御、魔法防御の値を常時表示する。デスクトップでは 6 項目を 1 行、狭い画面では 3 項目ずつ 2 行にする。項目名と値を省略せず、既存の計算値をそのまま使う。
- レベル帯は同じバーの下段に置く。4 つの切替ボタンを維持し、選択中・使用 Lv 数・上限を表示する。狭い画面ではボタン列だけを横スクロール可能な 1 行にし、選択中のボタンが切替後に見える位置へ来るようにする。切替ボタンをメニューへ隠さない。
- 現在の職業別内訳は Phase 2 の機能なので維持する。狭い画面では各切替ボタンの幅を一定にし、職業アイコンと数の列を折り返さずボタン内で横スクロールできるようにする。内訳の読み上げ名も維持する。全項目を一度に見せるために固定バーを縦に伸ばさない。
- 固定バーの高さ・文字サイズ・余白は幅 390px、高さ 844px を基準に調整し、編集領域を少なくとも画面の半分程度残す。ズームや文字拡大で内容を切り捨てない。固定バーが内容を覆わないよう背景、重なり順、`scroll-padding-top` を設定する。
- ステータス値は追加・入替・削除・自動調整・復元直後に更新する。レベル帯切替では値を再計算せず、表示中の帯と一覧だけを更新する。

職業と成長値の一覧は、デスクトップで編集領域の高さを画面の残りに合わせた独立スクロールにする。育成経路は同じ行の右に置き、必要なら内部だけをスクロールさせる。これにより一覧の最下段でも追加先が横に見える。育成経路が長いときは、帯の見出しと「選択を追加」を見失わない配置にし、配置済み職業のリスト部分をスクロールさせる。

幅 760px 以下では左右配置をやめ、固定バーの下に「職業と成長値」「育成経路」を縦に並べる。両者を一つの編集領域に収め、職業一覧に高さの上限と内部スクロールを与えて、育成経路が常に画面内に残るようにする。縦方向の短いドラッグでも追加できることを確認する。スクロール可能な領域はキーボードで到達でき、フォーカスしたボタンが隠れないようにする。狭い画面で全ページのスクロールを完全に禁止する必要はない。

`position: sticky` だけで左右の距離を埋める案は、下段の職業を表示するためにページを長くスクロールさせる。固定バーと育成経路を同時に追従させると狭い画面の操作領域を圧迫するため、上記の内部スクロール方式を採用する。固定バーや内部スクロールがドラッグライブラリの衝突判定・自動スクロールを妨げる場合は、表示位置を合わせるための CSS とスクロールコンテナを先に調整し、マウス・タッチ・ボタン操作の受け入れ条件を優先する。

## DnD 中の表示

`DragOverlay` の職業名・数量表示は内容幅に合わせる。まず `white-space: nowrap` と内容幅に沿う CSS を使い、×1・×10・×100 および長い職業 ID が 1 行になることを確認する。内容幅への追従がライブラリの制約で難しい場合は、100Lv の表示に収まる一定幅を採用する。ドラッグ中表示の文字列も「件」から「Lv」に変える。追加・入替のドロップ先判定とゴーストの追従位置は変えない。

## 文言と選択状態

「件」は育成計画の**成長に割り当てるレベル数**を表す箇所で「Lv」に統一する。対象は職業の追加ボタンの読み上げ名、配置済み職業の数、レベル帯の職業内訳、ドラッグ中表示、スクリーンリーダー通知、ヘルプ、該当するテストと README。表示は `1Lv`、`10Lv`、`100Lv` のように空白なしで統一する。`×1`・`×10`・`×100` というボタンの見た目と `0/90` などの容量表記は維持する。実行結果や非数量の一般語としての「件」、コード中の `count` や共有コード形式は変更対象にしない。

| 場所                       | 現在                              | 変更後                             |
| -------------------------- | --------------------------------- | ---------------------------------- |
| 育成経路の入替元ボタン     | 1 件を選択                        | 入替対象に指定。選択中は「選択中」 |
| 育成経路の入替先ボタン     | ここへ変更                        | 1Lv入替                            |
| 職業と成長値の入替先ボタン | この職業へ変更                    | 1Lv入替                            |
| 育成経路の削除ボタン       | 1 件削除                          | 1Lv削除                            |
| 配置済み職業の数量         | 9 件                              | 9Lv                                |
| 追加ボタンの読み上げ名     | fighter 10 件をドラッグまたは選択 | fighter 10Lvをドラッグまたは選択   |

`1Lv入替` は選択した入替元の 1 レベル分だけを変更する。元が複数 Lv でも 1Lv だけ減り、変更先が 1Lv 増える。入替先に同じ職業を指定した場合や、そのレベル帯で使えない職業は選べない。異なるレベル帯の配置済み職業を入替先にする操作も追加しない。

### 単一の選択状態

画面上の選択は「追加元: 職業と数量」「入替元: レベル帯と職業」「なし」の 3 状態のうち一つだけにする。`PathEditor` 内で一つの判別可能な状態として管理し、追加元を選ぶと入替元を解除し、入替元を選ぶと追加元を解除する。

- 追加元の × ボタンは、選択中の職業と数量を背景・枠線などで強調し、`aria-pressed` も付ける。同じボタンを再度押したら選択を解除する。別の数量・職業を押したら選択を移す。下部の「選択中: mage ×10」は削除する。
- 入替元の職業カードとボタンを強調する。未選択時のボタンは「入替対象に指定」、選択中は「選択中」とし、`aria-pressed` を付ける。選択中のボタンを再度押したら解除する。別の職業を押したら選択を移す。
- 追加成功後は追加元を維持し、同じ追加を繰り返せる。ボタンによる1Lv入替後も入替元の職業が残る間は指定を維持し、繰り返し入れ替えられる。最後の1Lvを入れ替えた場合と、削除・自動調整などで入替元の職業がなくなった場合は解除する。ドラッグによる入替成功後は入替元を解除する。レベル帯切替時には両方の選択を解除する。
- 選択中の枠線・背景はドラッグ可能な状態、ドロップ可能な状態、フォーカス表示と混同しない。色だけに頼らず「選択中」の文言またはボタン名・`aria-pressed` で伝える。
- ドラッグ開始時はボタンの選択状態を変更しない。クリックとドラッグの判定は既存の `@dnd-kit` に委ね、ドラッグ終了後に誤って選択が変わらないことを確認する。

## 注目するステータスとヘルプ

`FocusOptions` を「職業と成長値」の見出し直下、職業一覧より上へ移す。並べ替えの対象がこの一覧であることを明確にし、チェック状態とスコア算出・並び順は変えない。チャート画面側の注目ステータス UI は現在の位置を維持する。

育成計画の見出し横に、名前を「育成計画の使い方」とするヘルプボタンを置く。押すとブラウザー標準の `<dialog>` を `showModal()` で開き、閉じるボタン、Escape、背景クリックで閉じられるようにする。開いたらダイアログ見出しへ、閉じたらヘルプボタンへフォーカスを戻す。ダイアログ表示中は背後を操作できない。追加の UI ライブラリは導入しない。

ヘルプ本文は、削除する 2 つの説明に相当する内容を短くまとめる。初稿は次の内容とする。

> レベル帯を選び、職業の ×1・×10・×100 を育成経路へドラッグして追加します。ボタンを選んで「選択を追加」でも追加できます。配置済み職業を別の職業へドラッグすると、1Lv 分を入れ替えます。「入替対象に指定」を選んで「1Lv入替」でも操作できます。配置済み職業は「1Lv削除」で減らせます。

キーボード**ドラッグ**の Space・矢印キーの説明は画面とダイアログから外す。機能と専用テストは Phase 3 では維持する。通常の Tab・Enter によるボタン操作は維持する。`Accessibility.screenReaderInstructions` などライブラリがドラッグ操作中に伝える説明は、機能を残す間は維持する。

## 実装 PR と受け入れ条件

計画書のみの PR をマージした後、以下の 3 PR を順に作る。各 PR は直前の PR がマージされた `main` から作成し、それぞれ単独で型検査・既存テスト・ビルドが通る状態にする。文言・配置だけの変更は必要な既存テストの更新にとどめ、操作の振る舞いはブラウザーテストで確認する。README は利用可能になった変更と同じ PR で更新する。

### Phase 3 PR 01: 固定バーと編集領域

`EditorPage` で見出しとヘルプボタンの直後に `StatusSummary` と `LevelRangeSelector` を隣接する固定バーとして置き、その下に共有、自動調整、体格、編集領域をこの順で置く。`PathEditor` と CSS で一覧・育成経路のスクロールを構成する。

確認すること:

- 幅 1280px と 390px、高さ 844px で、一覧の先頭・末尾のどちらでも 6 ステータスとレベル帯切替が見える。
- 一覧末尾の ×1・×10・×100 から育成経路へドラッグして追加できる。マウス、タッチ相当、ボタン操作を確認する。
- 育成経路が多職業で長い場合も追加先と入替先に到達できる。スクロール領域とページに意図しない横はみ出しがない。
- 狭い画面でフォーカスを移した際にボタンが固定バーの下へ隠れず、ページズームや文字拡大で操作不能にならない。
- レベル帯内訳、自動調整後のステータス更新、共有 URL 復元後の表示が維持される。

### Phase 3 PR 02: 文言、ドラッグ中表示、単一選択

`PathEditor`、`LevelRangeSelector`、関連する読み上げ文と表示 CSS を更新する。`PathEditor` の二つの選択 state を単一状態へ置き換え、選択中スタイルと `aria-pressed` を追加し、下部の選択中表示を削除する。チャートや計算モデルの数値は変えない。

確認すること:

- ×1・×10・×100 のドラッグ中表示に不自然な改行がない。
- 入替と削除が常に 1Lv だけを変更し、視覚文言と読み上げ名が一致する。
- A→B と B→A の切替、同じボタンでの解除、別数量・別職業への切替、追加後とボタンによる入替後の維持、入替元がなくなった場合・ドラッグ入替後・レベル帯切替後の解除が仕様どおり動く。
- ドラッグ時に選択が誤変化せず、ボタンによる追加・入替が従来どおり上限と職業制限を守る。
- 文言に依存するコンポーネントテストとブラウザーテストが更新される。

### Phase 3 PR 03: 注目ステータスとヘルプ

`FocusOptions` を編集可能な職業一覧の中へ移し、ヘルプダイアログを追加する。画面上の 2 つの長い説明を削除する。README の操作説明を現行 UI に合わせる。

確認すること: 並べ替えと追加元の対応、ヘルプの開閉とフォーカス復帰、Escape と背景クリック、狭い画面での本文スクロール、キーボードドラッグの説明がヘルプに現れないこと。既存のキーボードドラッグテストは引き続き通る。

各 PR で `npm run check` と影響するブラウザーテストを実行する。PR 03 の終了時には `npm run test:e2e` で全体を確認する。受け入れ条件に関係するブラウザーテストを追加・更新し、専用テストが重複する場合は統合する。

## 仕様として固定する範囲

- キーボードドラッグ機能は維持するが、利用者向けヘルプでは案内しない。機能を削除する判断は別タスクにする。
- 職業の追加・入替・削除は各操作の現行の単位と制約を維持する。共有コード、Redux の経路形式、ステータス計算は変更しない。
- 内部スクロール導入後もボタン操作は常に利用可能にする。ドラッグ先へ移動できない端末条件をボタン操作で補えることを確認する。
- 移植元ページは要求の背景を示す参考資料とし、実装時の振る舞いはこの文書の仕様と受け入れ条件を基準にする。
