# Phase 1 リメイク計画

## 目的と完了条件

Dragon's Dogma: Dark Arisen の育成経路を組み立て、ステータスを確認・共有できる機能を、バックエンド不要の静的 SPA として提供する。Phase 1 は実際に利用できる機能の再現を完了条件とする。画面の大幅な再設計、アカウント、サーバー保存、新しい計算機能は対象外とする。

利用者が次を行える状態で完了とする。

1. レベル帯ごとに選択可能な職業を確認し、育成経路へ追加・削除・変更できる。1 回、10 回、100 回の追加指定は上限を超えずに動作する。
2. 注目するステータスを選び、職業の並び順とスコアを確認できる。体格の変更と育成経路の変更がステータス表示へ反映される。
3. 育成経路を含む URL をコピーし、その URL を開くと同じ経路・体格が復元される。不正な復元コードでは画面が壊れず、利用者にエラーを示す。
4. トップ、チャート、免責事項の経路へ移動できる。`/chart` は利用可能な表示を維持し、未実装の機能を完成扱いにしない。
5. マウス、タッチ、キーボードで主要な経路編集を操作できる。ドラッグ操作を使えない場合も追加・削除・変更の手段がある。
6. 静的ホスティングで直接アクセスとページ再読み込みができ、既存の `#/restore?c=...` 形式の共有 URL を読み込める。

## 採用する技術

| 領域         | 採用方針                                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 実行環境     | Node.js 24 LTS、npm。実装開始時にサポート状況を確認し、LTS 系のパッチ版を固定する。                                                |
| 言語・画面   | TypeScript の安定版、React 19。計算と復元コードの処理は React に依存しない関数にする。                                             |
| 開発・ビルド | Vite 8、`@vitejs/plugin-react`。静的ファイルを生成する。                                                                           |
| 経路         | React Router 7 の Declarative Mode と `HashRouter`。共有 URL のハッシュ形式を保つ。                                                |
| 共有状態     | Redux Toolkit 2、React Redux。育成経路、体格、注目ステータス、画面間で共有する選択状態を管理する。                                 |
| ドラッグ操作 | PR 03 の試運転結果により `@dnd-kit/react` 0.5.0 と `@dnd-kit/dom` 0.5.0 を採用する。                                               |
| テスト       | Vitest、React Testing Library、`@testing-library/user-event`、`@testing-library/jest-dom`、Playwright。DOM テスト環境は `jsdom`。  |
| 品質管理     | ESLint の flat config、`typescript-eslint`、React Hooks ルール、Prettier。型検査、lint、整形検査、テスト、ビルドを CI で実行する。 |
| UI           | Phase 1 では既存の見た目に必要な部品だけを採用する。UI 部品・アイコンの一括固定や新しいデザインシステムの導入はしない。            |

Node.js 以外のパッケージに一律の LTS 制度はないため、各 PR で安定版とサポート状況、React 19 との互換性を確認する。依存関係は lockfile に記録し、無条件の最新版追従はしない。サーバー通信がないため、データ取得用フレームワークや SSR は導入しない。

## PR 分割

各 PR は単独でレビューできる変更量に抑え、前の PR の受け入れ条件が通ってから次へ進む。画面を追加する PR では、該当機能のテストと README の必要な更新を同じ PR に含める。

移植する際は元のコンポーネント構成をそのまま再現することを目的にしない。各 PR の機能と受け入れ条件を保ちながら、責務が混在するコンポーネントは分割し、薄いラッパーや重複したコンポーネントは統合する。状態の置き場所と計算処理の境界も見直し、必要なリファクタリングを当該機能の PR に含める。レビューでは変更前後の振る舞いと新しい責務の境界を説明する。

### PR 01: SPA の土台と開発環境

**範囲:** Vite + React + TypeScript の最小アプリ、Node.js 24 LTS と npm の固定、lockfile、ESLint、Prettier、Vitest、Playwright、CI、開発コマンド、README のセットアップ手順。トップ・チャート・免責事項の空の経路を React Router 7 の `HashRouter` でつなぐ。静的ホスティングで動く `base` 設定を明示する。

**レビューで確認:** 新規チェックアウトからセットアップできる。型検査、lint、整形検査、単体テスト、ビルドが通る。各経路へ移動し、再読み込みしても表示される。生成物にバックエンドを必要としない。

### PR 02: 計算データと育成経路のモデル

**範囲:** 職業、レベル帯、成長値、体格補正、ステータス算出、注目ステータスのスコアとソートを純粋な TypeScript に移す。レベル帯の境界と選択可能な職業を型と検証で表す。

**レビューで確認:** Lv1、Lv2–10、Lv11–100、Lv101–200 の境界で正しい成長値を使う。体格補正、複数職業の合計、注目項目のスコアが代表例で一致する。無効な職業やレベル数は明示的に扱う。計算テストは UI を起動せずに実行できる。

### PR 03: ドラッグ操作ライブラリの試運転と採否

**範囲:** `@dnd-kit/react` で独立した試運転画面を作る。職業をレベル帯へドロップして追加する操作と、配置済み職業を別の職業へドロップして割り当てを変更する操作を、実際のデータ形と更新関数で試す。1/10/100 の数量指定、同一カード内のボタン、入れ子のドラッグ対象、ドロップ禁止時の表示、キャンセル、ドラッグ中のプレビューも確認する。

**採用基準:** マウス・タッチ・キーボードで上記 2 種類が操作できる。数量と職業の取り違え、二重更新、意図しないスクロール妨害がない。レベル上限・職業制限を守れる。スクリーンリーダー向けの操作説明とフォーカス表示を用意できる。React 19 と組み合わせたビルド・テストが通る。保守中の安定版を使える。

**判定と成果物:** 実ブラウザーでデスクトップとモバイル相当の操作を確認し、操作ごとの結果、既知の制約、採否と理由をこの文書に追記する。基準を満たせば採用して試運転コードを実装の土台にする。満たせなければ不足する操作を特定し、維持状況と入力方式を確認した代替ライブラリで同じ試運転を行う。いずれも基準を満たさない場合は、ボタンによる全操作を先に提供し、ドラッグ操作は別 PR の判断事項として記録する。採用判断だけで未完成の試運転 UI を公開しない。

**PR 03 の判定（2026-09-23）: 採用。** `@dnd-kit/react` と `@dnd-kit/dom` の安定版 0.5.0 を固定する。[React の導入手順](https://dndkit.com/react/quickstart/)、[センサー](https://dndkit.com/react/guides/sensors/)、[アクセシビリティプラグイン](https://dndkit.com/extend/plugins/accessibility/) の公開 API で必要な操作を構成できた。両パッケージの React 19 との組み合わせで型検査・ビルド・ブラウザーテストが通る。試運転は開発サーバーの `#/dnd-trial` で確認でき、公開ビルドには画面を含めない。

| 確認項目           | 結果                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| マウス             | ×10 をレベル帯へ追加し、配置済み職業を別の職業へドロップして変更できる。                                          |
| タッチ             | Chromium のモバイル相当環境で長押し後の追加と配置済み職業の変更ができる。                                         |
| キーボード         | Space、矢印キー、Space で追加・変更でき、Escape で取り消せる。                                                    |
| 数量・制約         | ×100 は空き 90 件で止まり、選択できない職業と満杯のレベル帯へのドロップは更新しない。各操作の更新回数は 1 回。    |
| 入れ子・プレビュー | ×1 と同一カード内の ×10/×100 を別のドラッグ元として扱える。ドラッグ中のプレビューとドロップ対象の強調を表示する。 |
| 代替操作           | ボタンだけで追加・変更・削除でき、無効な追加ボタンは押せない。                                                    |
| 操作案内           | 日本語の画面説明、ドラッグ中の読み上げ文、フォーカス表示を用意した。                                              |

試運転の状態更新は `src/trial/dnd/model.ts` に分け、PR 02 の育成経路型・レベル帯・職業制限を使う。`@dnd-kit` の ID は更新関数に渡す前に解析する。PR 04 ではこの境界と操作部品を土台に、実画面の状態管理へ接続する。

PR 04 では育成経路の追加・削除・変更を `src/domain/pathEditing.ts` に移し、試運転と Redux の双方が使う。ドラッグ ID の解析と編集部品は `src/features/pathEditor/` に置く。無効なドロップ先も衝突判定で検出し、共通更新関数で拒否する。これは無効な場所に重ねた際、近くの有効な場所へ意図せず追加されるのを防ぐため。

**残る確認:** 実機のタッチ操作、スクリーンリーダーでの読み上げ、長い画面でのスクロールとの干渉は、実画面を組み込む PR 04 と全体検証の PR 08 で確認する。試運転ではドラッグ開始をハンドルに限定し、タッチは 250 ms 長押し後に開始する。0.x 系のため、将来の更新では [変更履歴](https://dndkit.com/changelog/) と型検査・ブラウザーテストを合わせて確認する。

### PR 04: 育成経路の状態と編集画面

**範囲:** Redux Toolkit に育成経路、体格、選択中のレベル帯を置く。トップ画面にレベル帯ごとの職業一覧、追加・削除・変更、数量指定を実装する。PR 03 で採用した操作方式を組み込み、同じ更新関数をボタン操作からも呼ぶ。

**レビューで確認:** 各レベル帯の上限と選択可能職業を守る。数量指定時も上限で止まる。編集結果はレベル帯を切り替えても保持される。ドラッグの可否にかかわらず同じ育成経路を作れる。主要操作のコンポーネントテストとブラウザーテストが通る。

**実装上の分担:** Redux Toolkit に育成経路・体格・選択中のレベル帯を置く。`EditorPage` は画面の状態を接続し、`PathEditor` は試運転画面とも共用する入力 UI を担当する。育成経路の制約は `pathEditing.ts` に集約する。狭い画面では職業一覧をスクロールでき、ページをスクロールしてドロップ先を表示してからタッチ操作を行える。実機のタッチ操作とスクリーンリーダーによる確認は PR 08 でも継続する。

### PR 05: ステータス表示と職業比較

**範囲:** 現在の経路・体格からステータスを表示する。注目ステータスの選択、職業ごとの成長値・スコア表示、スコア順の並べ替えをトップ画面へ追加する。

**レビューで確認:** 体格と経路の変更が表示へ即時反映される。注目項目の切り替えでスコアと並び順が変わる。計算結果は PR 02 の関数に一本化される。代表的な操作のテストが通る。

**実装上の分担:** `StatusSummary` は Redux の育成経路と体格を PR 02 の `calculateStatus` へ渡した結果だけを表示する。`VocationComparison` は編集中のレベル帯について `getStatusGrowth` と `sortByFocusedStatIds` を使い、注目項目によるスコアと並び順を表示する。注目項目は Redux に保持し、レベル帯を切り替えても維持する。表示用コンポーネントに計算式を重複させない。

### PR 06: 共有 URL と復元

**範囲:** 復元コードの生成・解析、`#/restore?c=...` の読み込み、共有 URL のコピーを実装する。コードのバージョン、文字種、レベル帯ごとの長さ、職業制限、体格を検証する。URL は固定のホスト名を埋め込まず、配置先と `base` に合わせて組み立てる。

**レビューで確認:** 生成した URL で経路と体格を復元できる。既に共有された有効なコードを読み込める。不正・途中で切れたコードは例外で画面を壊さず、明確なエラーを表示する。URL を開き直しても復元できる。互換性を固定するテストとブラウザーテストが通る。

### PR 07: 残る経路と画面の仕上げ

**範囲:** チャート経路に現在利用できるステータス表示と職業選択を載せる。免責事項、ナビゲーション、レスポンシブな配置を整える。未実装の導線やプレースホルダーを公開画面から除く。

**レビューで確認:** トップ・チャート・免責事項を往復できる。画面間で共有状態が保たれる。狭い画面でも閲覧と編集ができる。キーボード操作、ラベル、フォーカス表示を確認する。

### PR 08: 全体検証と移行完了

**範囲:** 計算、編集、共有・復元、経路移動の一連のブラウザーテストを完成させる。静的配信のプレビューで直接アクセスと再読み込みを確認する。README に実際の起動・テスト・ビルド・公開手順を反映し、不要な依存関係や試運転コードを整理する。

**レビューで確認:** Phase 1 の完了条件がすべて通る。主要操作をデスクトップとモバイル相当の画面で確認できる。CI が通り、手順通りに静的ファイルを生成できる。既存の共有 URL の有効なサンプルが復元される。

## 実装時の判断事項

- 公開先の URL とサブパスが決まった時点で Vite の `base` と共有 URL の動作を確定する。ホスト名をコードへ固定しない。
- UI 部品、アイコン、チャートの表示方法は該当 PR の画面要件に合わせて選ぶ。不要な依存関係を先に追加しない。
- ドラッグ操作で数量や対象を判別するデータはアプリの更新関数に渡す前に検証し、UI ライブラリ固有の値を計算モデルへ持ち込まない。
- 計算・復元コードの互換性は、代表的な入力と既存共有 URL のサンプルで確認する。仕様と異なる入力への対応は、黙って値を補正せず利用者に示す。
- 移植対象の構造に不自然な分割、重複、密結合がある場合は、機能を追加する PR で直す。見た目上同じ動作でも、保守しやすい責務分担を優先する。
