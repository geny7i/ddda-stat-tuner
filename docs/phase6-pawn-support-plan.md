# Phase 6 ポーン対応計画

## 位置づけ

`workspace/phase6.md` と `workspace/phase6-questions.md` の回答を基に、採用仕様、実装範囲、PR分割、受け入れ条件を定める。回答内容をこの文書に取り込み、Git管理外の `workspace` を参照しなくても実装・レビューできるようにする。

この計画書の作成ではアプリの実装を変更しない。到達性の根拠は [ポーンの倍数調整の検証](phase6-pawn-rounding-verification.md)、現在の探索仕様は [Phase 5 倍数調整](phase5-rounding-adjustment.md) を参照する。探索の基準は現行のPhase 5実装であり、旧Phase 4計画のビーム探索や最大10Lvには戻さない。

## 目的と完了条件

育成計画を覚者・ポーンのどちらとして作るか選択でき、編集・自動調整・共有復元のすべてがその種別の職業制限を守るようにする。

1. 体格の上に「覚者／ポーン」のラジオボタンを設置し、新規利用時は覚者を選択する。
2. 種別を切り替えると、警告と確認を経て全レベル帯の職業入力をリセットする。キャンセル時は現在の計画を維持する。
3. ポーンではアサシン・マジックアーチャー・ミスティックナイトを選択・自動割り当てできない。
4. ポーンの5倍数調整は全完成経路で、10倍数調整は成立条件を満たす完成経路で、保証上限内の解を返す。
5. 10倍数調整が成立しない場合は、探索前に実行不可の理由が分かる。
6. 共有URL・復元コードに種別を保存し、既存コードは覚者として復元できる。
7. 覚者の既存機能、キーボード・ドラッグ操作、モバイル表示に回帰がない。

## 採用仕様

### 種別切り替えと入力のリセット

育成計画は1つだけ保持する。覚者用・ポーン用の別々の計画や、切り替え前の経路の自動復元は設けない。切り替えは両方向とも同じ挙動にする。

- 職業入力が1Lvでもある場合、種別を確定する前に確認を表示する。禁止職業が含まれるかどうかには依存しない。
- 文言は「ポーンに切り替えると、すべてのレベル帯の職業入力がリセットされます。体格は維持されます。」のように、切り替え先と失われる入力を明示する。
- 確認ボタンは「リセットして切り替える」、取消ボタンは「キャンセル」とする。Escapeによる閉鎖も取消として扱う。標準の `dialog` と既存ヘルプの実装を参考にし、フォーカスを適切に戻す。
- 確認前はラジオボタンの確定値・経路を変更しない。取消時は種別・経路・体格を維持する。
- 確定時は種別変更と4帯すべての経路消去を1回の状態更新で反映する。Lv1も消去する。
- 体格と注目するステータスは維持し、編集中の帯はLv1へ戻す。追加元・入替元・ドラッグ状態・古い自動調整結果を解除する。
- 職業入力が空なら、削除する内容がないため確認を省略して切り替える。同じ種別の再選択では何もしない。

共有コードの復元は、このリセット操作とは別に扱う。復元済みの種別・体格・経路を一括適用し、復元した経路をリセットしない。

### 職業制限と比較表示

| レベル帯              | 覚者                             | ポーン                                                               |
| --------------------- | -------------------------------- | -------------------------------------------------------------------- |
| Lv1、Lv2〜10          | ファイター・ストライダー・メイジ | 覚者と同じ基本3職                                                    |
| Lv11〜100、Lv101〜200 | 全9職                            | ファイター・ストライダー・メイジ・ウォリアー・レンジャー・ソーサラー |

ポーンで選べない3職は編集画面の一覧から非表示にする。手動追加、ボタン・ドラッグによる入れ替え、能力特化での未選択Lv入力、倍数探索のすべてで、同じ種別・レベル帯の制限を参照する。表示から隠すだけでなく、ドメインと状態更新でも不正な職業の混入を防ぐ。

比較チャートは**A案（種別に連動）を採用する**。回答では全職表示のB案を優先しつつ、A案の方が差分が少なければA案でよいとされている。現在、編集画面とチャートは同じ `selectComparisonRows` を使用しており、種別を入力に加える変更を共有できる。全職表示のための分岐や選択不可表示を追加するB案より変更が小さいため、A案とする。

チャートには現在の種別を表示し、その種別・帯で選べる職業だけを比較する。種別の切り替え操作は育成計画画面に置く。今回チャートの廃止は行わない。

### 倍数調整

全200Lvの職業入力を実行条件とし、Lv1〜10を維持する。ポーンの10倍数調整を成立させるために初期区間を自動変更する機能は追加しない。

| 種別・倍数  | 実行条件（完成経路に加えて）  | Lv11〜100 | Lv101〜200 | 合計上限 |
| ----------- | ----------------------------- | --------- | ---------- | -------- |
| 覚者・5／10 | 追加条件なし                  | 14Lv      | 12Lv       | 26Lv     |
| ポーン・5   | 追加条件なし                  | 6Lv       | 6Lv        | 12Lv     |
| ポーン・10  | Lv2〜10のメイジ成長回数が奇数 | 9Lv       | 14Lv       | 23Lv     |

Lv1の初期職業はメイジ回数に数えない。全5体格でこの条件は共通する。ポーンでメイジ回数が偶数のとき、Lv11以降の変更数を増やしても10倍数の解は存在しない。

- 現行の動的計画法を継続し、種別ごとの候補職業・変更上限を適用する。
- 前半ではメイジを新たに増やさず、既存のメイジを維持する選択は許す。
- 強みとスコアの低下を抑える評価、変更ペナルティの再探索、最後の変更数優先探索を維持する。最高スコア・全体の最小変更数・能力の完全維持は保証しない。
- 評価で使用する各能力の到達可能最大値も種別の職業制限から計算する。覚者の数値と評価は維持する。
- すでに全能力が指定倍数なら変更しない。前半の条件を満たす経路は前半を維持する。
- 入力を変更せずに経路を復元し、最後に実ステータス、職業制限、変更数を検証する。

10倍数が不可能なことは通常の結果として表し、例外や「もう一度お試しください」にはしない。UIと探索で条件判定を共通化し、探索関数を直接呼んでも不可能な経路を早期判定できるようにする。

UIでは10倍数の選択肢を残し、該当時は実行ボタンを無効にして次の説明を表示する。

> ポーンの10の倍数調整には、Lv2〜10でメイジとして成長した回数が奇数である必要があります。現在は○回のため実行できません。5の倍数への調整は利用できます。

未完成経路では、まず残りLv数と全200Lv入力が必要なことを案内する。Lv2〜10が未入力の段階で、現在のメイジ回数から最終的な不可能判定を表示しない。上記の説明は完成経路を対象にし、「5倍数を利用できる」と「未完成なので実行できない」が矛盾しないようにする。

変更上限の表示は種別と倍数に応じて26・12・23Lvに切り替える。前後ステータス・スコア・変更数の表示は維持する。

### 探索中の変更

種別を探索開始時の入力に含める。経路・体格に加えて種別の変更でも探索を中断または結果を破棄し、状態更新時にも照合する。

種別切り替え、復元、経路・体格変更で以前の結果が現在の計画の結果として残らないようにする。探索後に種別を往復した場合も古い非同期処理が結果表示や実行中状態を上書きしないよう、実行の識別または確実な中断を行う。

### 共有URL・復元コード

新形式には種別・体格・経路を保存する。URLの導線は維持し、コードのバージョンで新旧を識別する。新形式は覚者もポーンも種別を明示する。

- 既存形式は覚者として読み込み、種別以外の情報を変えない。
- 新形式は種別を検証したうえで、その種別の職業制限を適用する。
- 不明な種別、未知の職業、帯の上限超過、ポーンの禁止職業などは理由を表示して復元を拒否する。編集中の計画は変更しない。
- 正常な復元は種別・体格・経路を一括適用する。復元直後から職業一覧、自動調整条件、上限表示、チャート、再共有を一致させる。

ブラウザー終了後の自動保存や複数計画の保存は今回の範囲に含めない。

## 実装構成

種別は内部では `arisen` / `pawn` とし、正規化後のキャラクター情報と編集状態に明示的に保持する。旧共有コードからの既定値補完は読み込み境界で行い、未知の種別を覚者へ黙って変換しない。

種別・レベル帯に対応する使用可能職業の取得を共通化する。成長表そのものは変更しない。既存の職業順は維持し、同評価時の決定性を保つ。

主な変更箇所：

| 領域           | 対象と役割                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| ドメイン       | `character`、`vocations`、`levelRanges`、`pathEditing`、`pathAdjustment`：種別と制約、編集・自動入力の検証 |
| 倍数探索       | `roundingAdjustment`：実行条件、職業候補、上限、評価用最大値、不可能結果                                   |
| 状態と取得処理 | `editorSlice`、`selectors`：種別、リセット、比較職業、古い結果の防止                                       |
| 編集UI         | `EditorPage`、`PathEditor`、`AdjustmentControls`：切り替え確認、状態解除、実行可否・上限表示               |
| 非同期探索     | `runRoundingSearch`、`roundingWorker`：種別と結果型の受け渡し、中断・結果破棄                              |
| 共有           | `shareCode`、`RestorePage`、共有関連テスト：新形式、旧形式互換、種別ごとの復元検証                         |
| 比較・説明     | `ChartPage`、`EditorHelp`、README、ドメイン資料：種別表示と説明の整合                                      |

## PR分割と依存関係

計画書・到達性資料の整理をPR 00、実装を3つのPRに分ける。順序は **PR 00 → PR 01 → PR 02 → PR 03**。各PRは直前のPRがマージされた `main` から作成し、単独で型チェック・テスト・ビルドが通る状態にする。PR番号はPhase 6内の呼称であり、GitHubの番号ではない。

### PR 00：計画と到達性資料

範囲：この計画書と `phase6-pawn-rounding-verification.md`。現在作成済みの到達性テストはPR 02に含め、資料にはその検証結果と導入予定を記録する。

完了条件：回答した仕様、成立条件、上限、PRの依存関係を文書だけで確認できる。アプリの変更を含めない。

### PR 01：種別と職業制限のドメイン基盤

範囲：種別型、キャラクター情報の検証、共通の使用可能職業取得、手動編集と未選択Lvの自動入力への種別反映。既存アプリの呼び出し元・テストデータ・編集状態にも覚者を明示し、現状の動作を維持する。

この段階では種別切り替えUIと新共有形式は公開しない。共有は旧形式の覚者のみを扱い、ドメインからポーンを旧形式に出力して種別を失う操作は拒否する。ポーンの倍数探索もPR 02までは対応済みとして扱わず、直接呼び出しで覚者用探索へ流れないよう明示的に拒否する。これらの一時的な制約はPR 02・03で解消する。

受け入れ条件：

- 各種別・各レベル帯の使用可能職業が表どおりで、未知の種別を拒否する。
- ポーンの禁止職業がデータ検証、手動追加・入れ替え、未選択Lvの自動入力に混入しない。
- ポーンの能力特化入力は6職の中から最大成長値を選び、選択済みの入力を維持する。
- 覚者の選択順・計算値・同評価時の動作と既存共有コードの読み込みを維持する。
- UIから未完成のポーン機能へ入る経路を作らない。

検証：関連ドメイン・状態・共有テストを更新し、`npm run check` を実行する。既存編集・自動入力・共有復元の影響範囲をE2Eで確認する。

### PR 02：ポーン用倍数探索と保証の検証

範囲：種別別の職業候補・上限・最大値、不可能条件の早期判定、通常結果としての不可能理由を導入する。作成済みの `pawnRoundingReachability.test.ts` を含める。新しい結果型を既存の呼び出し元・Worker・表示側でも安全に扱えるようにするが、種別切り替えと共有によるポーン利用の公開はPR 03で行う。

受け入れ条件：

- ポーンの5倍数調整は、全初期職、全体格、各職業に偏った経路、固定シードの混在経路で成功する。
- ポーンの10倍数調整は、Lv2〜10のメイジ回数1・3・5・7・9で成功し、0・2・4・6・8で不可能結果を返す。初期職メイジを回数に含めない。
- 全状態列挙による到達性証明に加えて、実探索の復元結果を `calculateStatus` で再計算して確認する。
- 前半・後半・合計の各変更上限、Lv1〜10の維持、メイジ非増加、禁止職業の不在、元入力の不変性、決定性を検証する。
- すでに丸め済みの経路、前半条件を満たす経路、未完成経路を正しく扱う。
- 覚者の従来の到達性・品質回帰テストが通る。ポーンの代表的な特化経路で変更前後の能力・スコア・実行時間を確認し、必要な品質回帰テストを追加する。全経路共通の損失率保証は新設しない。

検証：`npm run check`、再現可能な代表経路の性能計測、既存の倍数調整E2Eを実施する。検証資料に実装後の結果と限界を反映する。

### PR 03：切り替えUI・共有復元・比較表示の統合

範囲：種別選択、リセット確認、種別連動の編集・チャート、倍数調整の条件・上限表示、新共有形式と旧形式互換、探索中の変更への対応、ヘルプ・README・ドメイン資料更新。

ポーンへの切り替えと共有・復元を同じPRで公開し、「作成できるが種別を共有できない」「復元できるが画面に種別や制限が反映されない」という中間状態を避ける。

受け入れ条件：

- 覚者→ポーン、ポーン→覚者の確認・取消・確定、空経路の切り替え、同じ種別の再選択が仕様どおり動く。
- 全帯の入力が消え、体格と注目項目は残り、Lv1へ戻る。古い選択・ドラッグ・結果表示が残らない。
- ポーンの一覧は6職、初期区間は3職となり、ボタンとドラッグ、自動入力のいずれも制限を守る。
- 10倍数不可能時は理由と実際のメイジ回数を表示して実行を無効化する。入力編集で条件が変わると表示も更新され、5倍数は実行できる。
- 種別・倍数ごとの変更上限が一致し、結果の能力・スコア・変更数が経路と一致する。
- 探索中の種別切り替え・体格変更・経路編集・共有復元で古い結果を適用しない。
- 新形式の覚者・ポーン、空経路・途中経路・完成経路を往復でき、旧形式は覚者として復元する。
- 不正な復元コードを拒否しても現在の計画は変わらない。正常復元では切り替え時のリセット確認を挟まず復元経路を表示する。
- 比較チャートが種別に連動し、現在の種別を表示する。
- デスクトップと幅390px相当で切り替え・確認・説明・結果を読める。キーボード操作、確認ダイアログのフォーカス移動・復帰、読み上げで操作内容と実行不可理由が分かる。

検証：状態・コンポーネント・共有テスト、上記操作のE2Eを追加・更新し、`npm run check` と `npm run test:e2e` を実行する。表示やフォーカスはブラウザーでも確認する。

## 完了時に残す記録

各PRに変更理由、受け入れ条件に対する検証結果、実装時に判断した差分を記録する。仕様や上限を変える必要が生じた場合は計画と根拠を更新する。最終的な資料には新共有形式、ポーンの実行条件、変更上限、切り替えで職業入力が消えることを残す。

この計画書の作成依頼は、PR作成・公開・マージや実装開始の依頼としては扱わない。
