# 育成経路とステータス計算

`src/domain/` は React や状態管理に依存しない計算モデルです。画面からは `src/domain/index.ts` を入口として利用します。

- レベル帯は Lv1、Lv2～10、Lv11～100、Lv101～200 の 4 つです。各帯の配列は、その帯で選んだ職業をレベル順に保持します。
- キャラクター情報は種別 `characterType`（覚者 `arisen`／ポーン `pawn`）、体格、育成経路を持ちます。内部データでは種別を必須とし、未知の値や省略を拒否します。
- Lv1～10 では両種別とも基本職 3 種のみ選択できます。Lv11 以降は覚者が全 9 職、ポーンがアサシン・マジックアーチャー・ミスティックナイトを除く 6 職です。`getAvailableVocations` が種別・帯に応じた選択可能職業を定義順で返します。
- 配列は帯のレベル数まで持てます。編集中の短い配列や空配列も有効です。追加・入れ替え・未選択Lvの自動入力にも種別を明示して渡し、入力と変更先の制限を検証します。
- ステータスは、経路に含まれる各レベルの職業成長値を足し、体格に応じた ST 補正を加えます。体格 `ss`、`s`、`m`、`l`、`ll` の補正はそれぞれ 0、20、40、60、80 です。
- 職業比較のスコアでは HP と ST を 10 分の 1、他の項目をそのまま加算します。注目項目が空なら全職業のスコアは 0 で、入力順を保ちます。
- `validateCharacterInfo` は未知の種別・体格・職業、種別や帯で選択できない職業、帯の上限を超える経路、欠けた帯を拒否します。計算前にも同じ検証を行います。

計算・並べ替えは入力を変更しません。復元 URL の解析や画面から受け取ったデータは、このモデルの検証を通してから利用します。

Phase 6 PR 02ではポーンの倍数探索まで対応し、画面は引き続き覚者の計画を編集します。既存の共有コードを読み込む境界で `arisen` を補い、旧形式でのポーン出力は種別が失われるため拒否します。種別切り替えUIとポーンの共有形式はPR 03で追加します。

倍数調整は `getRoundingEligibility` で未完成・実行可能・成立不可能を判定し、探索と画面で同じ条件を利用できます。ポーンの10倍数が成立しない場合、探索は例外ではなく `impossible` と理由 `pawn-mage-parity`、Lv2〜10のメイジ回数を返します。未完成経路は偶奇にかかわらず `incomplete` を返します。変更上限は `getRoundingChangeLimits` が返し、ポーンの5倍数は前半6／後半6Lv、10倍数は前半9／後半14Lv、覚者は従来どおり前半14／後半12Lvです。
